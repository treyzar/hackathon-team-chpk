# Образовательная платформа — кликабельный прототип

Прототип к кейсу хакатона «Образовательная платформа» (25–26 сентября 2026). Школьники 1–9 классов учатся программировать: ученик проходит курс сам, куратор сопровождает и проверяет работы, администратор собирает курсы.

Внутри все три курса базового пакета учебного содержания: 9 модулей, 30 шагов, шесть типов шагов. Все имена и данные вымышлены.

## Как запустить

- **Локально.** Откройте `index.html` в браузере. Нужен интернет: шрифты и интерпретатор Python загружаются из сети.
- **Через GitHub Pages.** Загрузите `index.html` в репозиторий, затем откройте `Settings` → `Pages` → `Deploy from a branch` → ветка `main`, папка `/ (root)` → `Save`. Через минуту-две сайт откроется по адресу `https://<логин>.github.io/<репозиторий>/`.

Сервер для работы прототипа не требуется. Состояние приложения автоматически сохраняется в `localStorage` браузера и восстанавливается после перезагрузки страницы или повторного открытия сайта в том же браузере. Кнопка «Сбросить» в тёмной полосе сверху очищает сохранённое состояние и возвращает исходные демонстрационные данные.

## Что можно показать

Роль переключается в тёмной полосе сверху, без повторного входа.

1. **Ученик Маша К.** — «Продолжить» ведёт к задаче «Сумма от 1 до N» с черновиком, в котором ошибка. «Отправить снова» показывает, какой тест не прошёл. Замените `range(1, n)` на `range(1, n + 1)`: шаг зачтён, рейтинг вырос. На главной — возвращённая работа «Стена 5 × 3» с комментарием куратора.
2. **Куратор Ольга Викторовна Н.** — очередь из 6 работ, проверка по критериям, «Зачесть» или «Вернуть с комментарием». Во вкладке «Ученики» — отставание с причинами, во вкладке «Вопросы» — вопросы, привязанные к шагам.
3. **Администратор Елена Николаевна Р.** — курс «Алгоритмика»: добавьте шаг, и появится черновик изменений. «Опубликовать изменения» выпускает версию 2. Во вкладке «Типы шагов» можно добавить новый тип, например «Видеоурок».

Другие демо-аккаунты: ученики Лёва С. (Scratch и Minecraft) и Даня В. (Алгоритмика), куратор Павел Андреевич С. (Алгоритмика). Остальные ученики выбираются в списке сверху.

## Модель данных

```
Курс   { id, status: draft | published, version, data, draft, log }
data   { title, short, grades, volume, tool, goal, modules[] }
Модуль { id, title, steps[] }
Шаг    { id, type, title, body, task }
```

- `type` — ссылка на реестр типов шагов (`SEED_TYPES`). Тип задаёт название, иконку, допустимые способы проверки и поля сдачи.
- `task.kind` — ссылка на реестр способов проверки (`KINDS`). Их пять:

| kind | Что делает ученик | Параметры `task` |
| --- | --- | --- |
| `read` | читает теорию | — |
| `choice` | выбирает один или несколько вариантов | `multi`, `options: [{ t, ok }]` |
| `number` | вводит число | `answer`, `hint` |
| `code` | отправляет код на Python | `limits: { t, m }`, `tests: [[ввод, ответ, пример?]]`, `ref` |
| `manual` | сдаёт работу куратору | `fields` (url, image, text, file), `labels`, `criteria`, `extra` |

- `body` — текст шага в простой разметке, её же редактирует администратор. Пустая строка начинает новый абзац, `## ` — подзаголовок, `- ` — пункт списка, `> ` — заметка, `**жирный**` — выделение. Программа пишется между строками `:::scratch`, `:::makecode` или `:::python` и `:::`: одна строка — один блок, отступ в 4 пробела — вложенность, «конец» закрывает цикл.
- Прогресс хранится отдельно от курса: попытки, сданные работы, прочитанная теория, вопросы и дни занятий. Всё привязано к `id` шага, поэтому правка и новая версия курса прогресс не стирают.
- Правки опубликованного курса копятся в `draft`. Ученики видят `data`, пока администратор не нажмёт «Опубликовать изменения».

### Новый тип шага

Код менять не нужно: добавьте тип во вкладке «Типы шагов» или запишите его в `SEED_TYPES`. Новый тип собирается из существующих способов проверки и сразу появляется в меню «Шаг» конструктора.

### Новый способ проверки

Каждый способ подключается в пяти местах:

1. запись в `KINDS` — название, режим и вес в рейтинге (`04-registry-and-demo-data.js`);
2. форма ответа для ученика в `taskHtml` (`07-student-step.js`);
3. проверка ответа в действиях `answer` или `run` (`10-actions-and-start.js`);
4. редактор параметров в `checkEditor` (`09-admin.js`);
5. параметры нового шага по умолчанию в `defaultTask` (`10-actions-and-start.js`).

## Правила платформы

- **Порядок шагов.** Следующий шаг открывается, когда предыдущий зачтён или отправлен куратору. Работа на проверке не закрывает дорогу дальше.
- **Статусы.** «Зачтено», «На проверке», «Возвращено», «Не прошло тесты», «В процессе», «Не начато» — у каждого своя пара «цвет + иконка», как в разделе 03 брендбука.
- **Рейтинг.** Вес шага задаёт способ проверки: прочитанная теория — 2 балла, контрольный вопрос или ответ числом — 4, задача с тестами — 10. Работа, которую принял куратор, тоже весит 10, наравне с автопроверкой. Каждый день серии занятий подряд даёт 3 балла, максимум 30. Ученик видит, из чего сложился итог, и сколько баллов не хватает до следующего места.
- **Отставание.** Статус видят только куратор и администратор, у каждого уровня указана причина.
  - «Замедлился» — 3–5 дней без входа, 3 неудачные попытки на одном шаге или возвращённая работа, которую не исправляют 2 дня.
  - «Выпадает» — 6 и больше дней без входа.

## Проверка Python

Код ученика выполняет интерпретатор [Skulpt 1.2.0](https://skulpt.org), он загружается с jsDelivr при первой отправке. Код работает в фоновом потоке (Web Worker). Когда время вышло, поток останавливается, поэтому бесконечный цикл не подвешивает страницу. Лимит времени равен лимиту из паспорта задачи, умноженному на `PY_FACTOR` (сейчас 2). Вывод сравнивается с ответом по словам, лишние пробелы и переводы строк не важны. Если браузер не даёт создать фоновый поток, код выполняется прямо на странице со встроенным таймером Skulpt, так медленнее.

## Чего нет в прототипе

- **Сервера и базы данных.** Состояние хранится в памяти страницы, у каждого, кто открыл сайт, своя копия.
- **Настоящего входа.** Аккаунт выбирается на стартовом экране.
- **Серверной проверки кода.** В рабочей системе код нужно проверять на сервере в песочнице, иначе ученик может подменить результат. Лимит памяти в прототипе не проверяется.
- **Хранения файлов.** Скриншоты остаются в памяти страницы, никуда не загружаются.
- **Уведомлений.** Нет писем и push-уведомлений о проверке и ответах.
